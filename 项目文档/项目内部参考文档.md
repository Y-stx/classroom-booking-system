## 第一部分：项目开发流程与思路

### 1.1 项目定位与目标

**做什么：** 一个面向高校场景的教室预约 + 使用登记闭环系统。

**为谁做：** 三类用户——学生、教师、管理员。

**核心闭环：**
```
预约教室 → 管理员审批 → 签到使用 → 签退登记 → 数据沉淀
```

这一闭环是整个项目的"主线剧情"，所有模块都围绕它展开。

### 1.2 技术选型理由

| 层 | 选型 | 为什么选它 |
|----|------|-----------|
| 前端框架 | Vue 3 | 渐进式，单文件组件清晰，生态成熟 |
| 前端 UI | Element Plus | 与 Vue 3 原生配合，组件丰富 |
| 前端构建 | Vite | 比 webpack 快很多，开发体验好 |
| 状态管理 | Pinia | Vue 官方推荐，比 Vuex 简单 |
| 路由 | Vue Router 4 | 官方路由 |
| HTTP | Axios | 拦截器机制能统一处理 token 注入和错误 |
| 图表 | ECharts | 仪表盘饼图/柱状图 |
| 后端框架 | Spring Boot 3.2 | Java 生态最成熟的快速开发框架 |
| ORM | MyBatis | SQL 可控，不黑盒，适合学习项目 |
| 数据库 | MySQL 8 | 关系型标准选择 |
| 缓存 | Redis | 存 JWT token，支持登出失效 |
| 认证 | JWT | 无状态，前后端分离友好 |
| 密码 | BCrypt | Spring Security 提供，自带盐值 |
| API 文档 | SpringDoc | Swagger 3.0，自动生成接口文档 |

**一个核心决策点：为什么用 JWT + Redis？**
- 纯 JWT 一旦签发无法主动失效（直到过期）
- 加上 Redis 存储 token 白名单：登出时删 Redis key，即使 token 没过期也无效
- 这样既保持了无状态的优势，又能支持"主动登出"功能

### 1.4 开发阶段与衔接逻辑

项目按"从底到上"的顺序构建，每一层都为上一层服务：

```
阶段 1: 数据库
  ↓ 提供 4 张表 + 初始数据
阶段 2: 后端数据访问层（Entity + Mapper）
  ↓ 提供 SQL 操作能力
阶段 3: 后端业务层（Service）
  ↓ 提供业务规则校验
阶段 4: 后端控制层（Controller）+ 安全层（JWT）
  ↓ 提供 RESTful API
阶段 5: 前端 API 封装
  ↓ 提供可调用的 JS 函数
阶段 6: 前端页面 + 路由 + 状态管理
  ↓ 提供用户界面
阶段 7: 联调 + 优化
```

**关键衔接点：**

1. **数据库 ↔ 后端**：`schema-and-data.sql` 建表 → MyBatis Mapper XML 写 SQL → Entity 字段对应表字段
2. **后端 Controller ↔ 前端 API**：Controller 路径 `/api/classrooms` → 前端 `classroomApi.getList()` 调用同一路径
3. **JWT 认证衔接**：后端登录返回 token → 前端存 localStorage → Axios 拦截器自动注入 `Authorization: Bearer xxx` → 后端拦截器校验
4. **角色分流衔接**：后端 JWT 携带 role → 前端 Pinia 存 role → 路由守卫按 role 分流到 `/student` `/teacher` `/admin`
5. **主题色衔接**：用户角色 → Pinia theme store → `--role-primary` CSS 变量 → 所有组件颜色联动

### 1.5 一次完整请求的全链路

以"学生创建预约"为例，追踪一个请求从点击按钮到数据入库的全过程：

```
[1] 学生在 ReservationList.vue 点击"提交预约"按钮
       ↓
[2] 调用 reservationApi.create(dto)    ← src/api/index.js
       ↓
[3] Axios 发起 POST /api/reservations
       请求头自动加 Authorization: Bearer <token>  ← Axios 拦截器
       ↓
[4] Vite dev 代理转发到 localhost:8080  ← vite.config.js
       ↓
[5] Spring Boot 接收请求
       JwtAuthInterceptor.preHandle() 校验 token
       ↓
[6] ReservationController.create()
       ↓
[7] ReservationServiceImpl.create(dto, userId)
       校验：教室存在? 可用? 时间合法? 人数? 冲突?
       ↓
[8] ReservationMapper.insert()         ← MyBatis XML
       ↓
[9] MySQL 执行 INSERT INTO reservation ...
       ↓
[10] 返回新预约 id → Service 包装成 Result → Controller 返回 JSON
       ↓
[11] 前端 Axios then(res) → ElMessage.success('预约成功')
```

**路由守卫逻辑（router/index.js）：**
```js
router.beforeEach((to, from, next) => {
  const userStore = useUserStore()
  // 1. 登录页直接放行
  if (to.path === '/login') return next()
  // 2. 没 token → 跳登录
  if (!userStore.token) return next('/login')
  // 3. 有 token 但访问了不属于自己角色的路由 → 跳回自己的 home
  if (to.path.startsWith('/student') && userStore.role !== 'STUDENT') return next('/login')
  // ... 类似处理 teacher / admin
  // 4. 正常放行
  next()
})
```

## 第二部分：各功能实现逻辑

### 2.1 用户登录功能

**涉及文件：**
- 前端：[Login.vue](file:///e:/教室预约与使用登记系统/frontend/src/views/Login.vue)
- 后端：[AuthController.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/controller/AuthController.java)
- 业务：[AuthServiceImpl.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/service/impl/AuthServiceImpl.java)
- 工具：[JwtUtil.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/security/JwtUtil.java)

**实现逻辑：**

```
1. 前端 Login.vue 提供 Tab 切换：
   - Tab 1：学生登录
   - Tab 2：教师/管理员登录
   Tab 切换时联动：副标题文字、主题色、测试账号列表

2. 用户输入用户名+密码 → 点击登录
   → 调用 authApi.login({username, password})

3. 后端 AuthController.login(LoginDTO)
   → AuthServiceImpl.login(username, password)

4. 业务层逻辑：
   a. SysUserMapper.findByUsername(username)  查用户
   b. 用户不存在 → 抛异常 "用户名或密码错误"
   c. status == 0 → 抛异常 "账号已禁用"
   d. BCryptPasswordEncoder.matches(rawPassword, user.password)
      不匹配 → 抛异常 "用户名或密码错误"
   e. JwtUtil.generateToken(userId, username, role)
      生成 JWT，过期时间 24 小时
   f. RedisUtil.set("jwt:" + userId + ":" + token, "1", 86400)
      把 token 存入 Redis，键含 userId 方便管理
   g. 返回 { token, user: { id, username, name, role, ... } }

5. 前端收到 token：
   a. userStore.setToken(token) → 存 Pinia + localStorage
   b. userStore.setUser(user)
   c. themeStore.applyRole(user.role) → 设置主题色 CSS 变量
   d. router.push(ROLE_CONFIG[user.role].homePath)
      按角色跳转到对应首页
```

**关键点：密码为什么用 BCrypt 而不是 MD5？**
- MD5 同一密码哈希值相同，可被彩虹表破解
- BCrypt 每次加密都生成不同哈希（自带随机盐），无法通过比对哈希破解
- 验证时用 `BCryptPasswordEncoder.matches(raw, hashed)`，它会从哈希里提取盐值重新计算

### 2.2 JWT 鉴权拦截

**涉及文件：**
- [JwtAuthInterceptor.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/security/JwtAuthInterceptor.java)
- [WebMvcConfig.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/security/WebMvcConfig.java)

**实现逻辑：**

```
WebMvcConfig 注册拦截器：
  addPathPatterns("/api/**")          拦截所有 /api 开头的请求
  excludePathPatterns(                 白名单：
    "/api/auth/login",                  登录
    "/api/auth/register",               注册
    "/swagger-ui/**",                   Swagger
    "/v3/api-docs/**",
    "/favicon.ico",
    "/error"
  )

JwtAuthInterceptor.preHandle(request, response, handler)：

  1. 取出请求路径 path
  2. 遍历白名单，path.startsWith(wl) → 直接 return true 放行
  3. 如果是 OPTIONS 预检请求 → 放行（CORS 需要）
  4. 从 Header 取 "Authorization"
     没有 或不以 "Bearer " 开头 → 401 "未登录或Token缺失"
  5. 截取 token（去掉 "Bearer " 前缀）
  6. JwtUtil.validateToken(token)
     签名不通过/已过期 → 401 "Token无效或已过期"
  7. JwtUtil.getUserId(token) → 解析出 userId
     RedisUtil.hasKey("jwt:" + userId + ":" + token)
     不存在 → 401 "登录已失效，请重新登录"
     （这一步实现了"登出失效"：登出时删 Redis key）
  8. 把 userId / username / role 存入 request.setAttribute
     后续 Controller 可以通过 @RequestAttribute 取出
  9. return true 放行
```

**白名单设计的意义：** 登录接口本身不需要 token（否则陷入鸡生蛋问题），Swagger 文档要能直接访问否则没法测试。

### 2.4 预约创建

**涉及文件：**
- 前端：[ReservationList.vue](file:///e:/教室预约与使用登记系统/frontend/src/views/ReservationList.vue) + [ClassroomList.vue](file:///e:/教室预约与使用登记系统/frontend/src/views/ClassroomList.vue) 的预约弹窗
- 后端：[ReservationController.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/controller/ReservationController.java)
- 业务：[ReservationServiceImpl.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/service/impl/ReservationServiceImpl.java)

**校验链（这是最复杂的业务逻辑）：**

```
create(ReservationDTO dto, Long userId)：

  1. 参数校验（@Valid 已在 Controller 完成）

  2. classroomMapper.findById(dto.classroomId)
     不存在 → BusinessException("教室不存在")

  3. classroom.getStatus() != AVAILABLE
     → BusinessException("该教室当前不可预约")

  4. 时间校验：
     dto.startTime >= dto.endTime
     → "结束时间必须晚于开始时间"
     dto.startTime < now()
     → "不能预约过去的时间"

  5. dto.attendees > classroom.getCapacity()
     → "预约人数超过教室容量(" + capacity + ")"

  6. 时间冲突检测（关键）：
     reservationMapper.findConflicts(
       classroomId, startTime, endTime
     )
     SQL: SELECT * FROM reservation
          WHERE classroom_id = #{classroomId}
            AND status IN ('PENDING', 'APPROVED')
            AND NOT (end_time <= #{startTime} OR start_time >= #{endTime})
     解释：查找该教室在 [startTime, endTime] 区间内
           已存在的有效预约（待审批或已通过）
     不为空 → "该时段已有其他预约，请选择其他时间"

  7. 构建 Reservation 实体：
     status = PENDING（新预约默认待审批）
     userId = 当前用户
     createdAt = now()
     approverId = null
     rejectReason = null

  8. reservationMapper.insert(reservation)
     事务内执行（@Transactional）

  9. 返回预约详情
```

**为什么时间冲突用 `NOT (A OR B)`？**
- 直觉："有冲突" = 时间段有交集
- 交集的反面 = "A 完全在 B 之前" 或 "A 完全在 B 之后"
- 完全不相交：`existing.end <= new.start OR existing.start >= new.end`
- 有交集 = NOT (完全不相交)
- SQL 写成 `NOT (end_time <= #{start} OR start_time >= #{end})`


### 2.7 使用登记（签到 + 签退）

**涉及文件：**
- 前端：[UsageLogList.vue](file:///e:/教室预约与使用登记系统/frontend/src/views/UsageLogList.vue)
- 后端：[UsageLogController.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/controller/UsageLogController.java)
- 业务：[UsageLogServiceImpl.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/service/impl/UsageLogServiceImpl.java)

**签到逻辑：**

```
POST /api/usage/check-in   body: { reservationId }

  1. reservationMapper.findById(reservationId)
  2. 校验：
     - 预约状态 == APPROVED → 否则报错
     - userId == 当前用户 → 否则报错
     - 当前时间在 [startTime, endTime] 范围内 → 否则报错
     - usageLogMapper.findByReservationId(reservationId) == null
       → 已签到过则报错
  3. 构建 UsageLog：
     checkInTime = now()
     checkOutTime = null  （未签退）
  4. usageLogMapper.insert(usageLog)
  5. 返回 UsageLog
```

**签退逻辑：**

```
POST /api/usage/check-out   body: { reservationId, actualAttendees, equipmentStatus, cleanliness, notes }

  1. reservationMapper.findById(reservationId)
  2. usageLogMapper.findByReservationId(reservationId)
     不存在 → "请先签到"
     已签退（checkOutTime != null）→ "请勿重复签退"
  3. 更新 UsageLog：
     checkOutTime = now()
     actualAttendees = dto.actualAttendees
     equipmentStatus = dto.equipmentStatus
     cleanliness = dto.cleanliness
     notes = dto.notes
  4. 同步更新预约状态：
     reservationMapper.updateStatus(reservationId, 'COMPLETED')
     （签退完成 = 预约完成）
  5. 返回更新后的 UsageLog
```

```

  - 有 notes 的记录：标签变可点击样式 + 小眼睛图标
  - 点击弹出备注气泡卡片
  - 无 notes 的记录：标签保持原样
```

**请求拦截器：**
```js
axios.interceptors.request.use(config => {
  const userStore = useUserStore()
  if (userStore.token) {
    config.headers.Authorization = `Bearer ${userStore.token}`
  }

})
```

**作用：** 每次请求自动从 Pinia 取 token 注入 Header，不用每个 API 手动写。

**响应拦截器：**
```js
axios.interceptors.response.use(
  response => response.data,  // 直接返回 data，省去 .data.data
  error => {
    if (error.response?.status === 401) {
      const userStore = useUserStore()
      userStore.clearAll()
      router.push('/login')
      ElMessage.error('登录已失效，请重新登录')
    }
    return Promise.reject(error)
  }
)
```

**作用：**
- 401 自动清登录状态 + 跳登录页
- 业务错误统一弹 ElMessage 提示

### 2.12 数据库初始化

**涉及文件：**
- [schema-and-data.sql](file:///e:/教室预约与使用登记系统/阶段1-数据库/schema-and-data.sql)
- [DataInitializer.java](file:///e:/教室预约与使用登记系统/backend/src/main/java/com/classroom/reservation/config/DataInitializer.java)

**SQL 脚本内容：**
```sql
-- 1. 建库
CREATE DATABASE classroom_reservation;

-- 2. 建 4 张表
CREATE TABLE classroom (...);
CREATE TABLE sys_user (...);
CREATE TABLE reservation (...);
CREATE TABLE usage_log (...);

-- 3. 插入初始数据
-- 教室 6 间
INSERT INTO classroom (name, building, ...) VALUES
('A201', '教学楼A', 2, 60, 'MULTIMEDIA', '投影仪,空调,音响,白板', 'AVAILABLE', ...),
...

-- 用户 3 个（admin / teacher01 / student01）
-- 预约 4 条（覆盖各种状态）
-- 使用登记 1 条
```

**DataInitializer 的作用：**

```
问题：SQL 脚本里的密码是假的 BCrypt 哈希（占位）
       直接用无法登录

解决：Spring Boot 启动时 DataInitializer.run() 执行：
  1. 查询所有用户
  2. 对每个用户：
     如果 password 不是 BCrypt 格式（不以 $2a$ 开头）
     → 用 BCryptPasswordEncoder.encode(原始密码) 重新加密
     → update sys_user set password = ? where id = ?
  3. 这样无论 SQL 里写的是什么，启动后密码都会被正确哈希
```

**为什么这样做？**
- SQL 脚本里直接写真实 BCrypt 哈希太长太丑
- 启动时修复是一次性成本，比手动改 SQL 更可靠
- 也方便后续在 SQL 里新增用户时直接写明文密码，启动自动修复

## 附录：常见问题排查

**Q: 登录返回 401 "Token无效或已过期"**
A: 后端 JWT secret 与签发时不一致，或 token 真过期（24小时）。重新登录。

**Q: 访问 /api/xxx 返回 401 "未登录或Token缺失"**
A: 前端 localStorage 没 token，或 Axios 拦截器没正确注入。检查 userStore.token 是否有值。

**Q: Swagger UI 404**
A: JwtAuthInterceptor 白名单没包含 /swagger-ui 路径。检查 WebMvcConfig.excludePathPatterns。

**Q: 端口 8080 占用**
A: `netstat -ano | findstr :8080` 找 PID，`taskkill /PID xxx /F` 杀掉。

**Q: 前端代理 404**
A: vite.config.js 里 `'/api': { target: 'http://localhost:8080', changeOrigin: true }` 配置是否正确。

**Q: 主题色不生效**
A: 检查 document.documentElement.style.getPropertyValue('--role-primary') 是否有值。theme.js 的 watch 是否触发。
