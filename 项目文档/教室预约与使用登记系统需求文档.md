## 二、项目概述

### 2.1 系统定位

本系统面向高校教室资源管理场景，提供教室预约、审批流程、使用登记（签到/签退 + 设备状况填报）一体化的 Web 解决方案。目标用户包括学生、教师、管理员三类角色，通过 B/S 架构实现浏览器访问。

### 2.2 业务价值

- **资源可视化**：教室资源集中展示，状态实时同步，避免冲突预约。
- **流程规范化**：预约 → 审批 → 使用 → 登记 → 归档闭环管理。
- **数据沉淀**：使用记录与设备状况留存，支持后续统计与维护决策。
- **角色协同**：学生/教师发起需求，管理员统筹审批，三方协作清晰。

## 四、功能需求

### 4.1 认证模块

#### 4.1.1 登录

- **输入**：用户名、密码。
- **校验**：非空校验 + 后端账号密码校验（BCrypt 比对）。
- **返回**：JWT token + 用户信息（含 role）。
- **存储**：token 存 localStorage，user 信息存 Pinia + localStorage。
- **失败提示**：账号或密码错误时显示友好提示，不暴露具体字段错误。

#### 4.1.2 登出

- 清除本地 token 与 user 信息。
- 调用后端登出接口（可选，失败不阻断前端清理）。

#### 4.1.3 获取用户信息

- 已携带 token 时调用 `/auth/info` 刷新用户资料。

#### 4.1.4 大写锁定提示

- 密码输入框检测 CapsLock 状态，开启时显示黄色警告条。

### 4.2 教室模块

#### 4.2.1 教室列表（学生/教师）

- **查询条件**：关键词（名称/楼栋）、类型、状态。
- **快捷筛选**：全部 / 可用 / 维护中 chip 切换。
- **展示形式**：卡片网格，含教室图片区、状态徽章、类型标签、容量进度条、设备图标。
- **交互**：卡片 hover 3D 倾斜跟随、图标脉冲、预约按钮。
- **分页**：默认 12 条/页，支持翻页。

#### 4.2.2 教室详情

- 点击可用教室卡片弹出预约对话框，展示教室信息（楼栋、容量、类型）。

#### 4.2.3 教室管理（管理员）

- **增删改查**：新增教室、编辑教室、删除教室、按条件查询。
- **字段**：名称、楼栋、楼层、容量、类型、状态、设备描述、备注。
- **状态切换**：可用 / 维护中 / 停用。

### 4.3 预约模块

#### 4.3.1 发起预约

- **必填**：预约主题、开始时间、结束时间。
- **选填**：使用目的、预计人数。
- **校验**：结束时间须晚于开始时间；教室须处于可用状态。
- **冲突检测**：后端校验同教室同时段不可重复预约。

#### 4.3.2 我的预约（学生/教师）

- **列表展示**：预约主题、教室、楼栋、时段、人数、状态、操作。
- **快捷筛选**：全部 / 待审批 / 已通过 / 已完成 chip。
- **操作**：
  - PENDING / APPROVED 状态可取消（需填写取消原因）。
  - APPROVED 状态可签到。
- **状态流转**：PENDING → APPROVED/REJECTED → COMPLETED / CANCELLED。

#### 4.3.3 取消预约

- 弹窗填写取消原因，调用 PUT `/reservations/{id}/cancel`。

#### 4.3.4 预约状态流转

```
PENDING ──通过──> APPROVED ──签到──> IN_USE ──签退──> COMPLETED
   │                  │
   │驳回              │取消
   ▼                  ▼
REJECTED          CANCELLED
```

### 4.4 审批模块（管理员）

#### 4.4.1 审批队列

- **查询**：关键词搜索预约主题。
- **列表**：预约主题、教室、楼栋、预约人（带头像）、时段、人数、状态、操作。
- **操作**：通过 / 驳回。
- **统计概览**：待审批数、今日处理数、总记录数。

#### 4.4.2 通过审批

- 二次确认弹窗 → 调用 POST `/approvals/{id}/approve`。
- 记录审批人 ID 与审批时间。

#### 4.4.3 驳回审批

- 弹窗填写驳回原因（必填）→ 调用 POST `/approvals/{id}/reject`。
- 驳回原因回填至 reservation.reject_reason。

### 4.5 使用登记模块

#### 4.5.1 签到

- 从"我的预约"中 APPROVED 状态的预约入口进入。
- 调用 POST `/usage/check-in`，记录签到时间。
- 签到后弹窗提示"使用结束后请记得签退"。

#### 4.5.2 签退登记

- **必填**：实际人数。
- **选填**：设备状况描述（如"设备完好"、"投影仪故障"）、卫生评分（1-5 星）、备注。
- 调用 POST `/usage/check-out`，记录签退时间与登记信息。

#### 4.5.3 使用登记列表

- **查询**：关键词搜索预约主题。
- **展示**：预约主题、教室、登记人、签到时间、签退时间、实际人数、卫生评分、设备状况。
- **设备状况智能分类**：根据文本自动打标"良好 / 故障 / 一般"。

### 4.6 系统管理模块（管理员）

#### 4.6.1 教室管理 Tab

- 同 4.2.3。

#### 4.6.2 用户管理 Tab

- **增删改查**：用户名、姓名、角色、院系、手机、邮箱、状态。
- **新增**：需设置初始密码。
- **编辑**：用户名不可修改。
- **状态切换**：启用 / 禁用。

### 4.7 概览/数据统计模块（管理员）

#### 4.7.1 统计卡片

- 教室总数、可用教室、待审批、今日预约、总预约数、已完成、总用户数、维护中。
- 数字 easeOutCubic 滚动动画。

#### 4.7.2 图表

- **饼图**：预约状态分布（待审批/已通过/已完成/已驳回/已取消），弹性入场。
- **柱状图**：教室状态分布（可用/维护中/停用），渐变填充。

#### 4.7.3 最近预约

- 展示最新 5 条预约，带状态指示点与彩色标签。

### 4.8 个人中心模块

#### 4.8.1 资料修改

- 可修改：姓名、院系、手机、邮箱。
- 不可修改：用户名。

#### 4.8.2 修改密码

- 输入旧密码 + 新密码 + 确认密码。
- 前端校验两次密码一致。
- 密码安全提示卡片（至少 8 位、字母数字组合、避免常见密码）。

## 五、非功能需求

### 5.1 性能

- 首屏加载 ≤ 2s（生产构建）。
- 列表分页接口响应 ≤ 500ms。
- 路由切换 ≤ 300ms（含懒加载）。
- 图表渲染 ≤ 1s。

### 5.2 安全

- 密码 BCrypt 加盐哈希存储。
- JWT token 有效期 24h，登出失效。
- 前端角色校验仅用于路由分发与菜单显隐，所有数据访问由后端接口二次校验。
- 严禁前端硬编码敏感数据（密码、内部 ID 列表）。

### 5.3 可用性

- 玻璃拟态 + 渐变背景视觉风格，统一设计系统。
- 关键操作有动效反馈（按钮 hover、卡片入场、状态指示灯闪烁）。
- 空状态、加载状态、错误状态均有视觉反馈。
- 响应式适配：桌面端 ≥ 1280px 最佳，移动端基础可用。

### 5.4 可维护性

- 前端 SCSS 变量集中管理（颜色、阴影、圆角、动画曲线）。
- 后端分层清晰（controller / service / mapper / entity / dto / common）。
- API 定义集中维护（前端 `api/index.js`、后端 SpringDoc 自动生成）。
- 枚举类集中定义状态与类型常量。

### 5.5 兼容性

- 浏览器：Chrome / Edge / Firefox / Safari 主流版本。
- 数据库：MySQL 8.0+ 字符集 utf8mb4。
- 缓存：Redis 6+。

### 5.6 可测试性

- 后端：JUnit 5 单元测试 + Apifox 接口测试。
- 前端：Vitest 组件测试 + Playwright E2E 测试。
- 冒烟脚本：PowerShell 脚本覆盖关键接口。

## 七、接口规范

### 7.1 通用约定

- Base URL：`/api`（前端 Axios baseURL）。
- 请求头：`Authorization: Bearer {token}`（登录后）。
- 响应格式：`{ code: number, message: string, data: any }`，code=200 成功。
- 时间格式：`yyyy-MM-dd HH:mm:ss`。
- 分页参数：`page`（从 1 开始）、`pageSize`。
- 分页响应：`{ list: [], total: number }`。
