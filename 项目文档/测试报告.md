## 四、缺陷分析与修复

### 4.1 已修复缺陷

| 编号 | 缺陷描述 | 严重程度 | 修复方式 |
|------|----------|----------|----------|
| BUG-001 | 教室列表缺少最小容量筛选条件 | 中 | ClassroomQueryDTO 新增 minCapacity 字段，Mapper 添加 capacity >= #{minCapacity} 条件 |
| BUG-002 | 取消预约未校验预约是否已开始 | 高 | cancel 方法增加 startTime > now 校验 |
| BUG-003 | 取消预约允许 PENDING 状态，与指导书要求不符 | 中 | 状态校验改为仅 APPROVED 可取消 |
| BUG-004 | 缺少按日期时段查询空闲教室的接口 | 高 | 新增 GET /api/classrooms/available 接口，NOT EXISTS 子查询排除冲突预约 |
| BUG-005 | 缺少教室使用率和按周统计功能 | 低 | 新增 /api/dashboard/usage/classroom 和 /api/dashboard/usage/weekly 接口 |
| BUG-006 | 缺少批量预约功能 | 低 | 新增 POST /api/reservations/batch 接口，按周次批量生成 |
| BUG-007 | 缺少爽约标记查询 | 低 | 新增 GET /api/reservations/no-shows 接口 |

### 4.2 测试中发现的问题

1. **测试数据幂等性**：集成测试初次运行使用 plusDays(3) 的时间，重复运行时因数据库残留预约数据导致冲突测试。已将测试时间调整为 plusDays(60) 和 plusDays(120)，降低冲突概率。

2. **取消预约规则变更**：原实现允许 PENDING 状态取消，按指导书要求改为仅 APPROVED 可取消。此变更后 PENDING 状态的预约只能通过管理员驳回撤销，符合指导书业务规则。

## 五、测试结论

1. **核心业务闭环完整**：预约 → 审核 → 签到 → 签退 全流程功能正常，业务规则校验到位。
2. **异常处理完善**：时间冲突、超容量、权限不足、状态非法等场景均有明确错误提示。
3. **新增功能验证通过**：minCapacity 筛选、空闲教室查询、取消时间校验、使用率统计、批量预约、爽约标记等新增功能均通过测试。
4. **自动化测试覆盖率**：核心接口已有 MockMvc 集成测试覆盖，状态机和 DTO 归一化有单元测试保障。

**系统功能满足指导书要求，可进入交付阶段。**
