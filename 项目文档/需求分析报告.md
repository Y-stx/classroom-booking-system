## 一、项目概述

### 1.1 系统定位

本系统面向高校教室资源管理场景，提供教室预约、审批流程、使用登记（签到/签退 + 设备状况填报）一体化的 Web 解决方案。目标用户包括学生、教师、管理员三类角色，通过 B/S 架构实现浏览器访问。

### 1.2 业务价值

| 价值维度 | 描述 |
| --- | --- |
| 资源可视化 | 教室资源集中展示，状态实时同步，避免冲突预约 |
| 流程规范化 | 预约 → 审批 → 使用 → 登记 → 归档闭环管理 |
| 数据沉淀 | 使用记录与设备状况留存，支持后续统计与维护决策 |
| 角色协同 | 学生/教师发起需求，管理员统筹审批，三方协作清晰 |

### 2.3 路由设计

系统按角色拆分为三个独立工作区，各自有独立首屏和侧边栏菜单：

| 路径前缀 | 角色 | 首屏 | 菜单项 |
| --- | --- | --- | --- |
| `/student/*` | STUDENT | StudentHome | 工作台、教室预约、我的预约、使用登记、个人中心 |
| `/teacher/*` | TEACHER | TeacherHome | 工作台、教室预约、我的预约、使用登记、个人中心 |
| `/admin/*` | ADMIN | AdminHome | 管理工作台、审批中心、使用登记、系统管理、个人中心 |

路由守卫逻辑：
- 未登录用户重定向至 `/login`
- 已登录用户访问其他角色区域时重定向至本人首屏
- 旧路径（`/classrooms`、`/reservations` 等）自动重定向至角色首屏

## 三、功能需求

### 3.1 认证模块

#### 3.1.1 登录

| 需求项 | 描述 | 状态 |
| --- | --- | :---: |
| 输入 | 用户名 + 密码 | ✅ |
| 角色快捷入口 | 学生/教师/管理员三个 Tab，点击自动填充测试账号 | ✅ |
| 校验 | 前端非空校验 + 后端 BCrypt 密码比对 | ✅ |
| 返回 | JWT token + 用户信息（含 role） | ✅ |
| 存储 | token → localStorage，user → Pinia + localStorage | ✅ |
| 失败提示 | "账号或密码错误"，不暴露具体字段错误 | ✅ |
| 大写锁定检测 | 密码框检测 CapsLock，显示黄色警告 | ✅ |
| 主题切换 | 登录页右上角浅色/暗黑切换按钮 | ✅ |
| 动态背景 | Canvas 粒子数据流动画 | ✅ |

#### 3.1.2 登出

- 清除本地 token 与 user 信息
- 调用后端登出接口（失败不阻断前端清理）
- Redis 中删除 `jwt:{userId}:{token}` 登录态

#### 3.1.3 获取用户信息

- 已携带 token 时调用 `GET /api/auth/info` 刷新用户资料

#### 3.3.3 预约状态流转

```
PENDING ──通过──> APPROVED ──签到──> IN_USE ──签退──> COMPLETED
   │                  │
   │驳回              │取消
   ▼                  ▼
REJECTED          CANCELLED
```

| 状态 | 显示 | 颜色 | 可执行操作 |
| --- | --- | --- | --- |
| PENDING | 待审批 | 琥珀（闪烁） | 取消 |
| APPROVED | 已通过 | 绿 | 取消、签到 |
| REJECTED | 已驳回 | 红 | — |
| COMPLETED | 已完成 | 蓝 | — |
| CANCELLED | 已取消 | 灰 | — |

```
└── utils/            # JWT 工具、Redis 工具
```

### 8.2 认证流程

```
1. POST /api/auth/login
   → AuthController → AuthServiceImpl
   → 校验用户名密码（BCrypt 比对）
   → 生成 JWT token
   → Redis 存入 jwt:{userId}:{token}
   → 返回 { token, user }

2. 后续请求携带 Authorization: Bearer {token}
   → JwtAuthInterceptor 拦截
   → 解析 JWT 获取 userId
   → 检查 Redis 中 token 是否存在
   → 不存在返回 401

3. POST /api/auth/logout
   → Redis 删除 jwt:{userId}:{token}
```

### 8.3 核心业务规则

#### 预约创建规则（ReservationServiceImpl）

| 校验项 | 规则 | 失败结果 |
| --- | --- | --- |
| 教室存在性 | classroom_id 必须对应已有教室 | 返回错误"教室不存在" |
| 教室状态 | 教室状态必须为 AVAILABLE | 返回错误"教室不可用" |
| 时间合法性 | end_time > start_time | 返回错误"结束时间须晚于开始时间" |
| 时间冲突 | 同教室同时段不能有 PENDING/APPROVED 预约 | 返回错误"该时段已有预约" |
| 创建结果 | 状态设为 PENDING | 返回"等待审批" |

#### 预约状态流转规则（ReservationStatus 枚举）

| 当前状态 | 合法流转 |
| --- | --- |
| PENDING | → APPROVED, REJECTED, CANCELLED |
| APPROVED | → COMPLETED, CANCELLED |
| REJECTED | （终态） |
| COMPLETED | （终态） |
| CANCELLED | （终态） |
